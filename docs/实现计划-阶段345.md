## 背景

阶段 0–2 已完成：鉴权、漫画发布与阅读闭环。  
本文件覆盖一期 MVP 剩余能力：**用户治理、评论互动、站内消息**，以及收尾验收。

## 现状与缺口

| 已有 | 本计划要补齐 |
|------|----------------|
| 注册/登录、漫画 CRUD、列表/阅读 | 管理端用户列表/删号 |
| | 评论 / 回复 / 点赞 + 阅读页评论区 |
| | 管理端按页查看/删除评论 |
| | 站内互动消息（赞、回复） |

## 业务规则（沿用阶段 0）

- 评论：至少两级（评论 → 回复）；更深拍平为回复顶层
- 删父评论：级联删除子回复及相关点赞
- 删用户：软删失效并释放昵称（可同名重新注册）；评论显示「已注销用户」；回滚该用户点赞
- 点赞：仅针对评论
- 系统推送、消息精确定位楼中：二期，不在本计划

## 阶段 3：用户治理（管理站）

### 目标

管理员可查看、删除 App 用户；被删用户无法继续使用。

### 后端

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/admin/users` | 列表：id、昵称、头像 URL、注册时间、is_deleted |
| DELETE | `/api/admin/users/{id}` | 软删 `is_deleted=True` |

- 鉴权：admin JWT（`/docs`）或管理站 Session 直接调 service
- 被删用户：登录与 `/api/auth/me` 拒绝（现有 deps 已拦截 `is_deleted`）

点赞回滚：若阶段 3 时尚无 `likes` 表，本阶段只做软删；阶段 4 建表后在删用户逻辑中补回滚（或阶段 4 删除用户时统一处理）。

### 管理站

- `/admin/users`：列表 + 删除确认
- 首页导航增加「用户管理」入口

### App

- 可选：401 /「已注销」时清 Token 并回登录页（建议一并做）

### 验收

- [x] 后台能看到注册用户并删除
- [x] 被删用户无法再登录 / 调用需登录接口
- [x] App 401 清 Token 退登（已实现；真机目视可选）
- [x] 冒烟脚本：`backend/scripts/smoke_phase3.py`

### 建议工期

1–2 天

## 阶段 4：评论 + 回复 + 点赞

### 目标

阅读页可留言、回复、点赞；管理端可按页删评。

### 数据模型

```
Comment
  id, page_id, user_id, parent_id(nullable), content, created_at

Like
  id, user_id, comment_id
  unique(user_id, comment_id)
```

- `parent_id` 为空：顶层评论
- `parent_id` 指向顶层评论：回复（若传入更深 parent，拍平到该顶层）

### 用户 API（user JWT）

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/pages/{id}/comments` | 评论树；含赞数、当前用户是否已赞、作者昵称/头像（已注销显示文案） |
| POST | `/api/pages/{id}/comments` | body：content，可选 parent_id |
| POST | `/api/comments/{id}/like` | 点赞 |
| DELETE | `/api/comments/{id}/like` | 取消赞 |

### 管理 API / 管理站

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/admin/pages/{id}/comments` | 按页全部评论（含回复） |
| DELETE | `/api/admin/comments/{id}` | 级联删子回复 + 点赞 |

管理站：漫画列表增加「评论」→ 评论列表 + 删除。

### App

- 阅读页：漫画图下方同页竖滑进入评论区（满足「上滑看评论」）
- 发评、点「回复」带 parent、点赞/取消
- 作者已注销时显示「已注销用户」

### 删用户补全（与阶段 3 衔接）

- 软删用户时：删除（或回滚）该用户全部 `Like` 记录，并更新相关评论赞数展示逻辑

### 验收

- [x] 两账号互评、回复、点赞/取消赞
- [x] 后台删除父评后子回复消失
- [x] App 阅读页评论区已实现（真机目视可选）
- [x] 冒烟脚本：`backend/scripts/smoke_phase4.py`

### 建议工期

4–6 天

## 阶段 5：站内互动消息

### 目标

被点赞、被回复时，消息中心有记录与未读状态。一期不做系统推送。

### 数据模型

```
Notification
  id, recipient_id, actor_id, type(like|reply),
  comment_id, page_id, is_read, created_at
```

### 写入时机（嵌在阶段 4 的赞/回接口内）

- A 赞了 B 的评论 → 通知 B（自己赞自己不写）
- A 回复了 B 的评论 → 通知 B（自己回自己不写）

### 用户 API（user JWT）

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/notifications` | 列表（触发者信息、类型、关联页/评论摘要） |
| GET | `/api/notifications/unread-count` | 未读数（红点） |
| POST | `/api/notifications/{id}/read` | 单条已读 |
| POST | `/api/notifications/read-all` | 全部已读 |

### App

- 入口：顶栏或底部「消息」+ 未读角标
- 消息列表页
- 一期可不做点击跳转到精确楼层（二期）

### 验收

- [x] 被赞/被回后消息列表有记录
- [x] 未读数正确；标记已读后清零或减少

### 建议工期

2–3 天

## 实现顺序

```text
阶段3 用户治理 → 阶段4 评论互动 → 阶段5 站内消息 → 阶段6 收尾验收
```

原则：

1. 每阶段结束后用 `/docs` + 真机（或至少 API 冒烟）验收再进入下一阶段
2. 阶段 4 与阶段 5 不要并行大改，避免通知与评论逻辑缠在一起
3. 后端 API 先通，再接管理站与 App

## 目录落点（实现时）

| 能力 | 主要位置 |
|------|----------|
| 用户管理 API / 页 | `backend/app/api/`、`backend/app/admin/`、`templates/` |
| Comment / Like 模型 | `backend/app/models/` |
| 评论与点赞 API | `backend/app/api/` |
| Notification 模型与 API | `backend/app/models/`、`backend/app/api/` |
| 阅读页评论区 / 消息页 | `app/reader/.../ui/` |

## 明确不在本计划

- FCM / 系统通知栏推送
- 消息点击定位到具体评论楼
- 修改昵称/头像
- 多章节、敏感词、举报、禁言
