## 1. 项目背景与目标

### 1.1 背景

海外朋友创作的漫画为英文版。经作者同意后，计划进行汉化并发布。若等全部汉化完成再发布，等待周期过长，读者容易失去兴趣，也无法集中讨论。

### 1.2 目标

搭建「Linux 服务器 + Android 客户端」系统，实现：

1. **边汉化边发布**：管理员在后台上传已汉化的漫画页后，用户可尽快在 App 中看到。
2. **按页讨论**：每一页漫画支持评论、回复与点赞，便于集中交流。
3. **互动可达**：用户能收到与自己相关的互动消息（如被点赞、被回复/留言）。

### 1.3 成功标准（MVP）

- 管理员可完成漫画的增删改，以及评论、用户的管理操作。
- 用户可注册、浏览最新漫画页、在评论区留言/回复/点赞。
- 用户可在 App 内看到互动消息。
- 仅支持 Android 端（不做 iOS 双端）。

## 2. 系统范围

### 2.1 包含

| 端 | 面向对象 | 职责 |
|----|----------|------|
| 网页管理后台 | 管理员 | 漫画管理、评论管理、用户管理 |
| Android App | 普通用户 | 注册、阅读、评论互动、查看消息 |
| Linux 服务器 | — | API、图片存储、数据持久化 |

### 2.2 不包含（本期不做或列为后期）

- iOS / 鸿蒙原生客户端
- 双端统一跨平台发布要求
- 付费订阅、打赏、广告等商业化能力
- 复杂运营能力（敏感词库、举报工作流、内容推荐算法等）——可视后续需要再加
- 系统级推送（FCM 等）可作为二期；一期以 **App 内消息中心** 满足「收到互动消息」

## 3. 角色与权限

### 3.1 管理员

- 通过网页后台登录（与普通用户账号体系分离，建议独立管理员凭证）。
- 可管理漫画、评论、用户。
- 不可替代普通用户在 App 内发评论（除非后续单独需求）。

### 3.2 普通用户

- 通过 Android App 注册与登录。
- 可浏览漫画、发表评论/回复、点赞、查看与自己相关的互动消息。
- 不可访问管理后台，不可删除他人评论或用户。

## 4. 功能需求

### 4.1 网页管理后台（面向管理员）

#### 4.1.1 漫画管理

| 编号 | 需求 | 说明 |
|------|------|------|
| A-01 | 新增漫画/页 | 上传一页（或多页）漫画图片，并维护必要信息（如所属作品/章节、页码顺序、标题或备注等） |
| A-02 | 修改漫画 | 可更换图片、调整页序、修改标题/备注等元信息 |
| A-03 | 删除漫画 | 可删除指定页或整段内容；删除后用户端不可再访问该内容 |
| A-04 | 查看漫画列表 | 可浏览已上传内容，按时间或页序查看 |

#### 4.1.2 评论管理

| 编号 | 需求 | 说明 |
|------|------|------|
| A-05 | 按页查看评论 | 进入某一页漫画的评论区，查看该页下全部评论（含回复） |
| A-06 | 删除评论 | 可删除不当评论或回复；删除规则需明确是否级联删除子回复（见第 6 节） |

#### 4.1.3 用户管理

| 编号 | 需求 | 说明 |
|------|------|------|
| A-07 | 查看用户账号 | 列表展示现有用户（至少含：昵称、头像、注册时间、用户 ID） |
| A-08 | 删除用户账号 | 可删除指定用户；删除后的评论/点赞/消息展示策略见第 6 节 |

---

### 4.2 Android App（面向用户）

#### 4.2.1 账号

| 编号 | 需求 | 说明 |
|------|------|------|
| U-01 | 注册账号 | 填写名字（昵称），并上传图片作为头像 |
| U-02 | 登录 | 注册后可登录使用（具体凭证形式：昵称+密码或其他方案，实现阶段确定） |
| U-03 | 个人资料展示 | 至少能展示自己的昵称与头像（是否支持后期修改头像/昵称，可作为后续项） |

#### 4.2.2 漫画阅读

| 编号 | 需求 | 说明 |
|------|------|------|
| U-04 | 浏览漫画 | 可查看已发布的漫画页 |
| U-05 | 下拉刷新 | 通过下滑/下拉刷新，获取并展示最新漫画内容 |
| U-06 | 阅读与评论区衔接 | 沉浸阅读；点击漫画显示入口，再点右下角打开底部评论大面板（含最新/最热） |

#### 4.2.3 评论与互动

| 编号 | 需求 | 说明 |
|------|------|------|
| U-07 | 发表留言 | 在某一页评论区发布评论 |
| U-08 | 回复留言 | 可回复他人的评论（楼中楼/回复关系） |
| U-09 | 点赞 | 可对评论点赞（是否支持对漫画页本身点赞，默认本期仅评论点赞，除非另行约定） |
| U-10 | 取消点赞 | 建议支持再次点击取消（实现阶段确认） |

#### 4.2.4 互动消息

| 编号 | 需求 | 说明 |
|------|------|------|
| U-11 | 收到互动消息 | 当有人点赞自己的内容，或有人对自己留言/回复时，用户能收到消息 |
| U-12 | 消息列表 | App 内提供消息入口，可查看互动记录（类型、触发用户、关联内容、时间） |
| U-13 | 未读状态 | 建议支持未读/已读区分（红点或数字角标） |

> 一期以 **站内消息** 为主；系统通知栏推送列为二期增强。

## 5. 用户主流程（概要）

### 5.1 管理员发布流程

1. 管理员登录网页后台。
2. 上传已汉化的漫画页并保存。
3. 用户端可通过刷新获取到该页。

### 5.2 用户阅读与讨论流程

1. 用户注册（昵称 + 头像）并登录。
2. 打开 App，下拉刷新获取最新漫画。
3. 阅读某一页，点击漫画后通过右下角入口打开底部评论面板。
4. 留言、回复或点赞。
5. 若自己的评论被点赞/回复，在消息中心看到对应互动。

### 5.3 管理员治理流程

1. 在后台查看某页评论，删除违规内容。
2. 在后台查看用户列表，必要时删除账号。

## 6. 业务规则（已确认）

| 主题 | 已确认规则 |
|------|------------|
| 用户登录 | 昵称唯一 + 密码 |
| 评论回复深度 | 支持至少两级（评论 → 回复）；更深层级可拍平展示为回复某条 |
| 删除评论 | 删除父评论时，子回复一并级联删除 |
| 删除用户 | 软删失效并释放昵称（可同名重新注册）；评论显示「已注销用户」；回滚该用户点赞 |
| 点赞对象 | 仅评论点赞 |
| 昵称唯一性 | 活跃用户昵称唯一；软删后释放昵称 |
| 图片 | 漫画页与头像上传限制大小/格式；服务端保存到本地 uploads |
| 「最新漫画」 | 默认按发布时间倒序 |
| 漫画模型（阶段1–2） | 单表 ComicPage（title、page_no、image、时间） |
| 管理员账号 | 不入库，使用环境变量 ADMIN_USERNAME / ADMIN_PASSWORD |
| 用户侧漫画接口 | 必须登录（user JWT） |

## 7. 非功能需求

| 类别 | 要求 |
|------|------|
| 平台 | 客户端仅 Android；服务端运行于 Linux |
| 网络 | App 通过 HTTPS 访问服务器 API（上线环境建议强制 HTTPS） |
| 性能 | 漫画大图需懒加载/压缩，避免一次加载过多高清图导致卡顿或流量过大 |
| 安全 | 管理接口与用户接口鉴权分离；禁止普通用户调用删除类管理接口 |
| 可用性 | 小规模私密/半公开分发即可起步；是否上架应用商店另定 |
| 版权 | 需持有原作者对汉化发布的授权（产品前置条件，非功能实现项） |

## 8. 分期建议

### 一期（MVP）

- 网页后台：漫画增删改、评论查看/删除、用户查看/删除
- Android：注册（昵称+头像）、下拉刷新看最新页、沉浸阅读+底部评论面板（最新/最热）、评论/回复/点赞
- 站内互动消息（点赞、留言/回复）

### 二期

- 系统推送通知
- 消息点击跳转到对应漫画页/评论
- 个人资料修改、更完善的阅读体验

### 三期（可选）

- 举报、禁言、敏感词、评论置顶等运营能力
- CDN、更完善的图片处理与带宽优化

## 9. 验收要点（MVP）

- [x] 管理员可上传/修改/删除漫画页，用户刷新后结果正确。
- [x] 管理员可查看并删除某页评论。
- [x] 管理员可查看并删除用户账号。
- [x] 用户可注册（名字 + 头像）并使用 App。
- [x] 用户下拉可刷新到最新漫画。
- [x] 用户可打开底部评论面板，完成留言、回复、点赞（含最新/最热排序）。
- [x] 被点赞或被留言/回复后，用户能在消息中心看到对应记录。
