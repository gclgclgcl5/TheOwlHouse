## 1. 仓库目录约定

项目根目录拆成两套独立代码，互不混放：

```
TheOwlHouse/
├── docs/                 # 产品与技术文档
├── backend/              # 后端：REST API + 管理网站 + 本地数据/上传文件
├── app/                  # 前端：Android 用户端
└── README.md             # 总览与本地联调说明
```

| 目录 | 含义 | 面向对象 |
|------|------|----------|
| `backend/` | API 服务、管理网页、数据库与上传文件存储 | 管理员（网页）+ 给 App 提供接口 |
| `app/` | 仅 Android 客户端 | 普通读者 |
| `docs/` | 需求、选型、约定等文档 | 开发与协作 |

约定：

- **不要**把管理后台单独拆成第三个根目录；管理站属于 `backend/` 的一部分。
- **不要**在 `app/` 里塞服务端逻辑；App 只通过 HTTP 调用 `backend`。
- 本地上传的漫画图、头像等默认落在 `backend/` 内可配置目录（如 `backend/data/uploads/`），并加入 `.gitignore`。

## 2. 推荐技术栈（AI 主导选型）

选型原则：AI 实现与维护成本低、本地一键可跑、后期迁 Linux 服务器改动小。

### 2.1 后端 `backend/`（API + 管理网站）

| 层级 | 技术 | 说明 |
|------|------|------|
| 语言 / 框架 | **Python 3.12 + FastAPI** | API 清晰、文件上传方便、文档自带 |
| ORM / 数据库 | **SQLAlchemy 2 + SQLite** | 本地零配置；上线可换 PostgreSQL |
| 鉴权 | **JWT**（用户 App + 管理员后台分开） | 管理员与普通用户凭证隔离 |
| 静态资源 | 本地磁盘目录提供图片 URL | 先简单，后期可换对象存储 |
| 管理网站 | **Jinja2 服务端渲染页面**（同进程） | 与 API 同仓同启，适合管理员一人使用 |
| 运行 | **Uvicorn** | `0.0.0.0` 监听，供局域网手机访问 |
| 依赖管理 | `requirements.txt` + venv | 简单可复现 |

管理网站与 API 同属 `backend/`，例如：

- API：`/api/...`
- 管理页：`/admin/...`
- 上传文件：`/media/...`

### 2.2 前端 `app/`（Android）

| 层级 | 技术 | 说明 |
|------|------|------|
| 语言 / UI | **Kotlin + Jetpack Compose** | 现代 Android 官方推荐 |
| 架构 | 单模块起步（后续可再拆） | 先跑通联调 |
| 网络 | **OkHttp + Retrofit + Kotlin Serialization** | 调 FastAPI |
| 图片 | **Coil** | 头像与漫画页加载 |
| 本地配置 | 可配置 **Base URL**（局域网 IP） | 禁止写死 `localhost`（手机上无效） |
| 构建 | Android Gradle Plugin **8.4.2** + Gradle Wrapper **8.6**（对齐本机已有缓存） | 用 Android Studio 打开 `app/` 工程 |

本期仅 Android，不做 iOS。

### 2.3 本地联调约定（当前阶段）

- **暂不部署**到公网 / 你的 Linux 服务器。
- 在开发机启动 `backend`，监听 `0.0.0.0:<port>`。
- 手机与电脑同一 Wi‑Fi；App 中填写电脑局域网地址，例如：`http://192.168.1.8:8000`。
- Windows 防火墙需放行该端口；若连不上，优先检查 IP、端口与防火墙。

## 3. `backend/` 内部结构（骨架）

```
backend/
├── app/                    # Python 包（避免与根目录 app/ 混淆：此为 backend 内模块名）
│   ├── __init__.py
│   ├── main.py             # FastAPI 入口
│   ├── config.py           # 配置（主机、端口、密钥、上传目录）
│   ├── database.py
│   ├── models/             # SQLAlchemy 模型（后续填充）
│   ├── schemas/            # Pydantic 模型（后续填充）
│   ├── api/                # REST 路由（后续填充）
│   ├── admin/              # 管理网页路由与模板逻辑
│   └── services/           # 业务逻辑（后续填充）
├── templates/              # Jinja2 管理页模板
├── static/                 # 管理页静态资源（css/js）
├── data/                   # 本地数据（gitignore）
│   ├── app.db              # SQLite（运行后生成）
│   └── uploads/            # 漫画页、头像等
├── requirements.txt
├── .env.example
└── README.md
```

> 注意：仓库根目录的 `app/` 是 Android 工程；`backend/app/` 是 Python 包名。二者路径不同，勿混淆。

## 4. `app/`（Android）内部结构（骨架）

```
app/                        # Android Studio 工程根目录
├── settings.gradle.kts
├── build.gradle.kts
├── gradle.properties
├── gradle/wrapper/
└── reader/                 # 应用 Module（工程根已是 app/，模块不用再叫 app）
    ├── build.gradle.kts
    └── src/main/
        ├── AndroidManifest.xml
        ├── java/com/owlhouse/reader/
        │   ├── MainActivity.kt
        │   ├── OwlHouseApp.kt
        │   ├── ui/             # Compose 界面（后续）
        │   ├── data/           # Retrofit API、仓库（后续）
        │   └── config/         # Base URL 等
        └── res/
```

应用包名预定：`com.owlhouse.reader`。

## 5. 与需求的对应关系（实现映射）

| 需求能力 | 主要落点 |
|----------|----------|
| 漫画增删改、评论管理、用户管理 | `backend` 管理网站 + 管理 API |
| 用户注册、阅读、评论/回复/点赞、消息 | `app` + `backend` 用户 API |
| 下拉刷新最新页 | `app` 调用分页/列表 API |
| 图片上传与访问 | `backend` 存储 + `/media` 静态挂载 |
| 局域网测试 | Uvicorn `0.0.0.0` + App 可配置 Base URL |
